# LEARNINGS：playbook 根级项目（2026-11-17 迁移轮用户纠正原则）

1. 「迁到根目录」= 真迁移：全部可执行源、测试、必需 fixtures、操作文档落到新唯一权威位置并在新位置真实跑绿；仅复制 README、或把主要实现留在旧 CCA `.pi` 实验域，都不算完成。
2. 详细有源、诚实解释：用户亲自认可设计后，必须逐文件、逐命令退出码说明新增了什么；历史溯源（谁在旧域写了什么）与实质迁移分线并行，溯源结果只入 docs，不改写原证据。
3. 外部产品依赖显式化：CCA 冻结产品/SUT/git 目录一律 `--home`/环境变量显式输入，缺即响亮拒绝；不得把用户 workspace 绝对路径当隐式库依赖，不得为通过测试把绝对路径重新埋回默认值。
4. preexisting 与迁移引起严格分账：新位置失败的测试先在旧位置原样复跑对照；易失 /tmp 证据缺失导致的失败保持原断言（响亮失败/显式 skip），绝不弱化断言或自动换路径造绿。
5. 旧入口只留薄 wrapper（旧 mock.mjs 路径继续可挂载），实现不双权威；旧实验目录保原证据与取证工具，不删历史工件。
6. 运行产物进 target/test-artifacts 类 gitignore 目录，不进版本树；私有证据（DB/key/原始 capture/实验日志）永不入 repo。
