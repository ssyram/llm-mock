# 执行契约：管理单元与自然边界

本契约适用于 `mock2.mjs`；作者入口见 [language.md](language.md)。

## 数据与职责

```text
ManagementUnit = RVUnit | UserBlock | SegmentBlock
RVUnit = Response + Validation
Response = say（默认空）+ tools（可空）
ProgramCounter = 当前函数帧 + 管理单元位置
ReadPointer = transcript 中的结构位置
```

label 是管理单元属性，不是可执行节点。Aggregation 是 Validation 中的处理者，不是第四种管理节点。参数、局部变量、调用帧和 continuation 是解释器数据，不能因此增加作者的控制块。

## RVUnit

前置：位于完整单元入口，或解释器正在恢复该单元的真实回执处理。

1. 生成或重放一条 Response，say 和相邻工具调用不被拆开。
2. 工具回执按 call ID 归属，允许到达顺序不同；无预测也要读取真实回执。
3. 执行已声明的 Validation；完成前不提交后继跳转，不伪造工具已执行。
4. 单元完成后，才在管理边界选择下一单元、调用或返回。

无工具的 Response 自然结束宿主 turn。完成本轮输出后，不因为下一节点是 Segment 就继续计算；必须等新的用户激活。重发相同请求、恢复缓存或收到工具回执不等于新用户。

## UserBlock

User 是独立管理单元，不是 RV Validation。遇到 User 时，上方收集的 Response 与其验证形成完整 RV；这是 User 定义边界的作用，不应以“禁止 label 切开 RV”误禁 User 的插入。

前置：执行到 User，或函数入口已有待匹配的新用户输入。

- 收束上方执行；已有纯 say 就直接停等，否则插入一条空 say 停止自动续行。
- 挂起期间不执行后续单元；新用户到来后执行本块匹配，首匹配决定继续或跳转。
- 连续 User 各自需要新的用户消息，中间有空回复边界。
- 首次根入口的 User 不为不存在的前序输出多造一轮交互；子函数没有尚未消费的新输入时仍停等，不能重复消费旧消息。

此停止不能撤销已经交给宿主的工具。已发批次的真实结果须按既有单元处理，不以空 say 丢弃在途工作或绕过验证。

## SegmentBlock 与 Aggregation

Segment 从完整 RV 入口接管，在管理边界返回；纯计算可以不消费 RV、不输出 Response。文件形式按参数压入新函数帧，EOF 返回调用者。

Aggregation 初次接管当前工具结果的 Validation；它可以当场完成，也可以处理后续完整单元再交还。它与 Segment 的声明格式相同，但输入含义与控制过程不同，不能合并语义。它发出后续 Response 后，解释器按完整 RV 处理回显与回执，并在当前 Validation 起点恢复同一处理者；这属于内部挂起续行，不是一个新的公开管理入口。普通函数调用或 label 跳转不能借此切入 RV 内部。

两种处理者都不能接管解释器栈或 ProgramCounter。它们返回的 ReadPointer 必须真实改变对应的历史消费位置；省略保持，不是另存一个与消费无关的 marker。

## 控制与数据不变量

- 函数、普通跳转和 label 只落在管理边界；没有公开的普通 resultEntry 跳点。
- 参数与局部变量按函数帧隔离；save 只存当前函数声明的局部值，不开放整个帧。
- 同一次动态执行的工具 ID 唯一；历史回显必须与已产生的调用内容一致。
- 一个 RV 无 aggregation 时，至多一个局部结果块持有后继跳转权；有 aggregation 时由它统筹后继，局部结果不能另跳。
- 步数与深度预算终止内部死循环，不以无限挂起代替错误。
- User、纯 say、工具等待和处理者挂起的原因由解释器保存，不由作者声明 phase/mode/end。

## 操作规约与组合论证

编译：源码 → 三种管理节点和 label 表；拒绝未知目标、RV 内 label 及非法结构，不能部分编译后继续执行。

推进：在当前管理边界处理节点；输出则保存回显/等待状态，等待则不越界；完成才选择后继。文件调用只在边界压帧，EOF 返回保持调用者等待状态。

外接：按外接协议选择完整 transcript、阅读位置和显式值；只应用合法数据返回、阅读推进或一条 Response。进程/协议错误硬停，不能当作 match 未命中。

恢复：continuation 保存函数帧、执行位置、阅读位置、待回显 Response、未完成 Validation 和等待用户的状态。恢复不能将 pending 回显当已确认历史，也不能将重复请求当新激活。

组合理由：编译提供完整节点边界；推进与调用只使用这些边界；外接没有栈/PC通道；恢复保存同一挂起原因。因此低层回执处理可以暂停在 Validation，但作者仍只有三种管理节点，不获得半单元跳转能力。

## 缓存边界

缓存是内部优化，不是另一种作者流程。键保留所有影响执行的已知输入和代码依赖；不能删掉命令可见的 metadata 来制造命中。真实输入前缀、待回显输出和 continuation 必须分清，同请求复用与历史扩展分别处理。

命中和冷重建的可观察回复/控制结果应一致；volatile 不复用其后的处理结果；空闲 TTL、存活请求保护和清理并发不能改变输出正确性。完整历史对外可读，阅读指针不构成访问权限；不得以仍隐藏未来前缀的旧规则描述新数据流。
